How it works

Four steps from key to confirmation

Every step is a single URL call. Responses are JSON, errors carry proper HTTP status codes.

1

Create master key

Generate a 6 character master API key from the admin panel or the create-key endpoint.

2

Connect Gmail

Log in once with a Google App Password. The gateway verifies IMAP access and returns a gmail key.

3

Generate QR

Pass a UPI ID and amount. You get an order ID plus a logo-branded QR as URL and base64.

4

Verify payment

Poll the verify endpoint. The inbox is scanned for a matching credit and the UTR is returned.

API reference

Endpoints

All endpoints accept GET and POST. Parameters may be sent in the query string, as form fields or as JSON.

Good to know

Important notes

Logo QR

QR codes render at error correction level H with the FamPay mark on a white badge in the centre, so they stay scannable.

15 minute window

Pending orders switch to expired automatically. Generate a fresh QR for a retry.

Two key layers

The master key authorises the app; the Gmail key selects which inbox is scanned during verification.

App Passwords only

Gmail requires 2-Step Verification plus a 16 character App Password. Normal passwords are rejected.

Amount matched

A credit is accepted only when the amount matches to the paisa and the UTR has not settled another order.

Rate limits

60 requests per minute per IP by default; QR creation is capped at 30 and logins at 10.
