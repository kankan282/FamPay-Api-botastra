# Deploying FamPay Gateway v2.0 on Render.com

Estimated time: **15 minutes** (Docker build takes 5–10 of them).

---

## Step 1 – Push the code to GitHub

> **The repository must contain the extracted files, with `Dockerfile` in the root.**
> Uploading the ZIP itself makes Render fail with
> `failed to read dockerfile: open Dockerfile: no such file or directory`.

### Option A – Git command line (recommended, keeps hidden files)

```bash
unzip fampay-gateway-v2.0.zip        # creates the fampay-gateway/ folder
cd fampay-gateway                     # Dockerfile must be here, at the top level

git init
git add -A                            # includes .htaccess, .gitignore, .env.example
git commit -m "FamPay Gateway v2.0"
git branch -M main
git remote add origin https://github.com/YOUR_USERNAME/YOUR_REPO.git
git push -u origin main
```

After pushing, the GitHub file list must show `Dockerfile`, `render.yaml`, `index.html`, `qr.php`, … **directly** – not a ZIP and not a single folder.

### Option B – GitHub website upload

1. Extract `fampay-gateway-v2.0-ROOT.zip` (this variant has no wrapper folder).
2. Repository → **Add file → Upload files**.
3. Select **all** extracted files and folders (`api`, `assets`, `migrations`, `tests`) and drop them in.
4. Commit.

Windows/macOS hide dot-files, so `.htaccess`, `.gitignore` and `.env.example` may not be uploaded this way. That is not fatal: `apache-config.conf` contains the same rewrite rules and file protections, so the deployment behaves identically. Add the dot-files later through **Add file → Create new file** if you want them in the repo.

### Option C – Keep the folder and tell Render where it is

If your repository looks like `YOUR_REPO/fampay-gateway/Dockerfile`, do not re-upload anything – in the Render service open **Settings → Build & Deploy → Root Directory** and set it to `fampay-gateway`. (With a Blueprint, add `rootDir: fampay-gateway` under the service in `render.yaml`.)

`vendor/` and `.env` are excluded by `.gitignore` – that is intentional, the Docker build runs `composer install`.

## Step 2 – Create a Render account

1. Sign up at <https://render.com> and verify your e-mail.
2. Connect your GitHub account (Account Settings → GitHub → Configure).
3. Grant access to the `fampay-gateway` repository.

---

## Step 3 – Deploy the blueprint

1. Dashboard → **New +** → **Blueprint**.
2. Select the `fampay-gateway` repository.
3. Render reads `render.yaml` and proposes:
   - Web service `fampay-gateway` (Docker, free plan)
   - PostgreSQL database `fampay-db` (free plan, database `fampay`, user `fampay_user`)
4. Click **Apply**. Both resources are created and linked automatically – all `DB_*` variables plus `DATABASE_URL` are injected for you.

> Prefer manual setup? Create the PostgreSQL instance first (**New + → PostgreSQL**), then **New + → Web Service**, choose *Docker*, and add the environment variables from `.env.example` by hand.

## Step 5 – Wait for the build

- Watch **Logs** → the Docker build installs `imap`, `gd`, `pdo_pgsql`, `zip`, `opcache` and runs Composer.
- The entrypoint prints `configuring Apache to listen on port 10000` – Render's `$PORT` is applied automatically.
- Wait until the status turns **Live** and the health check on `/` passes.

---

## Step 6 – Initialise the database

The schema is created automatically on the first request (`db_ensure_schema()`), so simply open:

```
https://your-app.onrender.com/test-db.php
```

All four tables and eight indexes must report **PASS**. To apply the migration manually instead:

1. Render dashboard → `fampay-db` → **Connect** → copy the *PSQL command*.
2. Run it locally and execute:

```bash
psql "postgres://...render.com/fampay" -f migrations/001_initial_schema.sql
```

## Custom domain

1. Web service → **Settings** → **Custom Domains** → *Add Custom Domain*.
2. Add the `CNAME` record Render shows at your DNS provider (e.g. `pay.example.com → your-app.onrender.com`).
3. Wait for verification – Render issues a free TLS certificate.
4. Update `APP_URL` to the new domain so `image_url` and `verify_url` are generated correctly.

## Troubleshooting

| Symptom | Cause / fix |
| --- | --- |
| `failed to read dockerfile: open Dockerfile: no such file or directory` | The repository contains the ZIP (or a wrapper folder) instead of the extracted files. Push the extracted project so `Dockerfile` sits in the repository root, or set **Root Directory** to the sub-folder (Step 1, options A–C). |
| `Dockerfile` present but build says "transferring dockerfile: 2B" | Only a placeholder/empty file was uploaded. Re-upload the real `Dockerfile` (2.4 KB). |
| Build fails on `docker-php-ext-configure imap` | Ensure `libc-client-dev` and `libkrb5-dev` are in the `apt-get install` list (they are in the bundled Dockerfile). |
| Service stuck in "Deploying", health check times out | Apache is not on `$PORT`. Confirm `docker-entrypoint.sh` is copied, executable, and used as `ENTRYPOINT`. |
| `503 SERVICE_UNAVAILABLE` from an endpoint | Database unreachable – check `DB_*` / `DATABASE_URL` and set `DB_SSLMODE=require`. |
| `IMAP_UNAVAILABLE` | The host lacks `ext-imap`. Deploy the Docker image (not a plain PHP runtime). |
| `IMAP_LOGIN_FAILED` | Use a 16-character **App Password**, not the account password; 2-Step Verification must be on. |
| Orders instantly expired | Fixed in v2.0: the PostgreSQL session time zone is aligned with `APP_TIMEZONE`. Ensure both service and database use the same value. |
| QR has no logo (`has_fampay_logo: false`) | `assets/fampay-logo.png` missing from the image, or GD not installed. Check `/test-qr.php`. |
| `429 RATE_LIMITED` during testing | Defaults: 60 req/min per IP (30 for `/qr.php`, 10 for `/create-key.php` and `/login.php`). Tune with `RATE_LIMIT_*`. |
| Free instance is slow on the first call | Render free web services sleep after 15 minutes of inactivity; the first request wakes them (~30 s). Free PostgreSQL expires after 30 days. |
| Admin panel returns "Invalid CSRF token" | Cookies blocked or the session expired (2 h). Reload `/cpanel-admin-2025` and sign in again. |
